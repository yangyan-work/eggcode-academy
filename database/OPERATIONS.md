## 3. Auth、RLS 与可信服务端权限

以下均为真实环境验收项。当前 SQL 准备稿、浏览器隐藏入口或本机管理员体验不能证明它们已通过。

- [ ] 注册、邮箱确认、登录、退出、找回密码、回跳与错误路径实际验证；只展示真实返回结果。会话切换时清除前一账号缓存，本机数据上传需由用户明确选择。
- [ ] 浏览器只持有允许公开的项目地址与 publishable key。数据库密码、secret / service_role 等高权限凭据仅由可信服务端保管，不放入静态文件、日志或导出包。
- [ ] 所有个人业务表启用 RLS；用匿名用户与两个真实账号 A/B 核验读取、新建、修改、删除。A 无法通过改 UUID、路径或请求正文读写 B 的数据。
- [ ] RPC 从真实会话确定身份，限制参数、长度、课程编号及并发版本；不能相信前端传来的用户或管理员编号。
- [ ] 投稿作者只能维护自己的可编辑稿件和图片，不能自行修改审核状态、审核备注或共享快照。正式管理员由服务端可信身份核验，不能来自用户可修改的 metadata、昵称或前端开关。
- [ ] 草稿桶与审核配图桶保持私有。审核正文和图片读取授权一致；下架后拒绝新正文读取和新图片下载／签名，已签发 URL 与缓存另行核查。
- [ ] 上传后端检查实际文件解码、MIME 与扩展名、尺寸和总量，移除不必要的图片元数据，执行容量与频率限制；客户端校验不能代替后端限制。
- [ ] 审核图片复制成功后，事务写入共享正文与审核状态；失败副本登记清理。可读正文不能引用未复制成功或未授权的图片。

## 4. 举报、下架与回复记录

远程收件当前未开通。开通前必须确定实际收件方式、处理人、证据保存位置、访问权限和回复方式；在网页公布真实渠道后才可以称为已收件。不要编造邮箱，也不要把本机保存成功显示为举报已送达。

举报材料只收集：教程／作品 URL 与标题、具体章节／步骤／图片位置、问题或权属关系说明、希望采取的措施，以及可核对的原作品链接、发布时间或必要授权证据。截图应遮盖无关个人信息。不要求身份证照片、家庭住址、密码、验证码、密钥或完整私人聊天记录。

审核负责人按以下顺序处理：

1. 登记编号、收到时间、内容位置、必要证据位置与处理人，确认能否准确定位；缺少关键材料时说明补充范围。
2. 核查问题和来源；有持续暴露风险或权属待核实的内容先暂停展示，记录理由，再向作者核实。不能把举报自动视为结论，也不能无限期保持争议内容公开。
3. 服务端把共享正文标为下架／暂停，阻止新的正文及图片授权，再调用 Storage 管理 API 清理相应审核图片，核查已签发 URL 的有效期和缓存。已下载文件无法远程收回。
4. 记录更正、维持、下架或恢复展示的结论、依据、执行结果与失败项；恢复展示需重新核对内容、来源和图片权限。
5. 通过已经开通的渠道回复处理结果，保留回复时间与内容摘要；允许补充证据和复核。尚未设置处理人和工作安排时，不写固定响应时限。

处理日志只保存必要摘要，原始证据分开限权保存。不要把举报者个人资料写进公开教程、公开仓库或共享审核备注。

```text
举报编号／处理人／收到时间：
页面 URL／稿件版本／具体位置：
问题与希望措施／证据保存位置：
临时处理／作者核查／最终结论及理由：
正文访问状态／图片清理／签名与缓存核查：
执行失败项／重试记录：
回复方式／时间／摘要／复核结果：
```

## 5. 真实账号删除：待实现

当前仅有本机清理和部分内容删除，不提供真实账号删除服务。退出登录、本机草稿删除、浏览器站点清理与真实 Auth 账号删除是不同操作；本机稿件删除也不能撤回已提交快照。

后端实现至少需要：

1. 提供本人可导出的业务数据和图片清单，说明删除影响、可能保留的必要处理记录及备份保留期限。用户先完成导出，再明确申请删除；当前完整云端导出尚待实现。
2. 使用有效登录会话与必要的再次认证核验本人。服务端自行取得目标身份，拒绝伪造、越权和重复操作；受信任后台调用管理接口，前端没有高权限删除能力。
3. 在数据库事务内记录删除任务、冻结该账号新增写入并保存业务记录和 Storage 路径清单。清单必须覆盖草稿、审核图片、未引用对象和需处理的共享快照；保留公开内容的规则需预先说明，不能默默保留关联个人信息。
4. 使用 Storage API 删除实际文件，逐项记录结果；不要直接删除 `storage.objects` 元数据冒充文件清理。业务数据按已验收方案事务删除，或在删除 Auth 身份时执行已验证的外键级联；最后核查 Auth 身份、业务表、文件与会话处理。
5. 数据库事务只能覆盖数据库变更，Storage 与 Auth 管理调用不能合为一个原子事务。任务必须有明确阶段、幂等重试和失败状态；失败时保持写入冻结与任务证据，未全部核查前不向用户宣称删除完成。
6. 记录完成时间及必要的删除清单，限制其访问和保留期限。备份按预先公布的周期到期处理；恢复旧备份时先重新应用已批准删除／下架清单，再开放读取与写入，避免已删账号或争议内容重新出现。

真实删除验收需覆盖本人成功删除、A 删除 B 被拒绝、重复申请、Storage 部分失败、数据库事务失败、Auth 删除失败、超时后状态重读、任务重试和恢复后的删除重放。任何高权限验证不得把凭据打印到日志。

## 6. 数据库与图片分别备份、恢复演练

试用备份建议：每天有变更时导出一次数据库，发布、迁移和批量删除前额外导出；同期单独备份 Storage 文件。此为本站计划，不是平台自动提供的承诺。至少保留最近 7 个有效版本，并在开放前确定正式保留周期、访问人和到期清理方法；账号删除说明应与该周期一致。

| 备份对象 | 必须保存 | 恢复后核查 |
| --- | --- | --- |
| 数据库 | 结构与业务数据、导出范围、结构版本、导出时间、校验值；Auth 范围另行确认 | RLS、RPC、用户关联、课程编号、进度版本和审核状态 |
| Storage 图片 | 草稿与审核文件实际字节、桶／路径、MIME、大小、校验值，以及正文引用映射 | 文件可读性、私有桶配置、授权、正文对应与孤立文件 |
| 删除与下架清单 | 经批准的对象和任务阶段，分开限权保存 | 恢复后重放，核对内容未重新开放 |
| 静态网站 | 完整版本快照、资源版本和允许公开的配置 | 页面入口、回跳、导航、缓存和错误提示 |

异地备份放在与项目分开的受保护位置，数据库与图片包不进入静态部署或公开 Git 仓库。备份内可能包含个人数据，按用途限权，避免在试用记录中复制完整内容。

开放前至少演练一次：

- [ ] 在隔离环境恢复数据库，确认导出是否包含所需 Auth 数据；缺失部分有经过验证的恢复／重新认证方案，不能凭文件存在宣称可恢复。
- [ ] 恢复图片实际文件与映射，核对每张引用图的校验值和授权；只恢复数据库不能视为图片已恢复。
- [ ] 重放删除与下架清单后，再用 A/B 和匿名身份做权限核查，确认争议内容、已批准删除的数据没有重新出现。
- [ ] 记录恢复用时、可恢复到的时间点、预期和实际数据损失、失败项及重测结果。用演练结果定义恢复目标，不先承诺零损失或即时恢复。

## 7. Free 计划、用量监控与上传限额

本轮只使用 Free；不升级付费，也不启用付费计算、备份附加项或其他付费服务。官方 Free 不收费的说明，不等于不限容量、不限带宽或保证可用性。

维护者在试用开始与每个试用日查看当前项目配额和用量，记录数据库容量、Storage 容量、流量、Auth 活跃用户、错误和异常上传。以 Dashboard 当时的免费配额为准，不在本稿固定可能变化的平台数值。

- 现有稿件约束：仅 PNG／JPEG／WebP，单图最多 **2 MiB**，单篇图片合计最多 **8 MiB**。正式后端与桶配置需实际拒绝超限、伪造格式和异常尺寸。
- 小范围试用建议增加：每位作者累计图片最多 **20 MiB**、每天最多 **10 次图片上传**，总参与者先限制为 **5 人**。这是待服务端实现的本站试用限额，不能把前端提示称为已强制执行；上线前按实测用量调整并记录。
- 任一监控项达到当前免费配额的 **80%**、出现持续异常请求或无法可靠统计时，先暂停新增上传与扩大邀请，整理非必要测试文件，保留可导出内容，再复核原因。到平台限制或故障时清楚显示失败，不假装已保存。
- 未引用图片和上传失败副本按任务记录清理，删除前确认没有被草稿或审核正文引用；禁止为节省空间直接删有效用户文件。
- 未来如确需付费，应另行核对预算、审批与费用规则，当前没有该授权。Spend Cap 不是精细预算，也不能替代人工用量监控。
